# Задача: 10 профессий со статусом «Скоро» (всего 13 в каталоге)

Поставлено 07.11.2026. Небольшая задача, делается одним шагом и одним коммитом.

## Что нужно

В каталоге должно быть 13 профессий: 3 доступные (QA, Python, Java — уже есть) и 10 со статусом `soon`. Список и тексты — в `backend/migrations/seed/soon/professions.yaml` (черновик, тексты не переписывай без нужды).

## Как сделать

1. `internal/content/seed.go`:
   - в `LoadSeed` читать `seed/soon/professions.yaml` (сейчас подкаталоги пропускаются, файл уже встроен через `//go:embed all:seed`) в отдельный список `SoonProfessions` (поля: slug, title, description, for_whom, sort_order);
   - `validate` для них проверяет только: slug уникален и не совпадает с доступными профессиями, title не пустой; блоки/темы/навыки не требуются;
   - `ApplySeed`: upsert в `professions` со статусом `soon` (`ON CONFLICT (slug) DO UPDATE` title, description, for_whom, sort_order). **Не понижать статус**: если профессия уже `available` (её наполнили и перенесли в отдельный файл), не трогать её статус.
2. Порядок: `sort_order` 1–3 — доступные, 4–13 — «скоро». Каталог сортирует по `sort_order`.
3. Карточка `GET /api/v1/professions/{slug}` для `soon` уже отдаётся (catalog.go) — проверь, что для неё возвращается профессия без блоков и это не ошибка 500. `% соответствия`, оценка и план для `soon` — 404 или понятная ошибка `profession_not_available`; опиши код в `api/openapi.yaml`.
4. Тест `seed_test.go`: доступных профессий 3, «скоро» — 10, всего 13, slug не пересекаются.
5. Проверка: `docker compose exec api /app/api seed` на базе с уже загруженными данными (повторный запуск безопасен), `GET /api/v1/professions` отдаёт 13 профессий, у 10 `status: soon`.

## Чего не делать

- Не создавать для «скоро» блоки, темы, навыки и материалы — их делает команда позже.
- Не трогать `frontend/` (зона Жени). Если фронтенд показывает «скоро» некорректно (кликабельно, ошибка при открытии) — напиши Юрию, что поправить, одной строкой для Жени.

## Как потом наполнять профессию

Скопировать структуру `qa-manual.yaml` в `seed/<slug>.yaml` (тот же slug), заполнить и удалить запись из `soon/professions.yaml`. После `api seed` профессия станет `available`.
